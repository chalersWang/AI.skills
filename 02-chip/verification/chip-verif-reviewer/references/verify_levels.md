# 验证层级详解

## 概述

芯片验证按照层次划分，通常分为四个层级：ST、IT、BT、UT。不同层级关注点不同，测试颗粒度也不同。

## 四级验证体系

### 层级对比总览

| 层级 | 全称 | 颗粒度 | 关注重点 | 测试入口 | 测试周期 |
|------|------|--------|---------|---------|---------|
| **UT** | Unit Test | 最细 | 信号级、功能点 | RTL/Netlist | 每次提交 |
| **BT** | Block Test | 较细 | 模块功能、边界 | RTL | 每日/每周 |
| **IT** | Integration Test | 中等 | 模块接口、协议 | RTL | 每周 |
| **ST** | System Test | 最粗 | 系统整体 | Gate-level | 每月/版本 |

## UT - 单元测试 (Unit Test)

### 特点

- **颗粒度**: 最细
- **测试对象**: 单个模块内部的功能单元
- **仿真时间**: 最短
- **覆盖率要求**: 高，通常要求100%功能覆盖率

### 关注点

1. **信号级验证**
   - 单个信号的功能正确性
   - 信号之间的组合逻辑
   - 同步/异步电路边界

2. **功能点验证**
   - 状态机所有状态转换
   - 计数器精度
   - 运算单元正确性

3. **接口协议（内部）**
   - 内部握手信号
   - 内部仲裁逻辑
   - 内部FIFO空满判断

### 典型测试点

```
UT-001: 状态机从IDLE到READY状态转换正确
UT-002: 状态机从READY到IDLE状态转换正确
UT-003: 计数器从0计数到255正确
UT-004: 计数器溢出后正确归零
UT-005: FIFO空时RD_EN不输出数据
UT-006: FIFO满时WR_EN不写入
UT-007: 组合逻辑输出在规定周期内稳定
UT-008: 异步复位信号有效
```

### 判断标准

测试点是否属于UT级：
- [ ] 是否针对单个信号或简单组合逻辑？
- [ ] 是否不涉及模块间接口？
- [ ] 是否可以快速仿真（<1分钟）？
- [ ] 是否可以穷举测试（状态机全部状态）？

## BT - 模块测试 (Block Test)

### 特点

- **颗粒度**: 较细
- **测试对象**: 单个IP/模块完整功能
- **仿真时间**: 中等
- **覆盖率要求**: 高，组合覆盖率>90%

### 关注点

1. **模块功能完整性**
   - 所有功能点的覆盖
   - 配置-功能对应关系
   - 工作模式切换

2. **边界条件**
   - 输入边界值
   - 配置极值
   - 协议边界

3. **错误处理**
   - 非法输入响应
   - 超时机制
   - 错误恢复

4. **模块级接口**
   - 寄存器读写
   - 中断生成
   - 本地内存访问

### 典型测试点

```
BT-001: SPI模块主模式发送1字节数据正确
BT-002: SPI模块主模式接收1字节数据正确
BT-003: SPI时钟分频配置生效
BT-004: SPI模式0/1/2/3切换正确
BT-005: CRC计算正确（已知模式验证）
BT-006: FIFO阈值中断触发
BT-007: 错误标志位正确置位
BT-008: 软件复位完整复位模块
```

### 判断标准

测试点是否属于BT级：
- [ ] 是否针对单个模块完整功能？
- [ ] 是否涉及寄存器配置？
- [ ] 是否涉及模块内部状态机？
- [ ] 是否不涉及其他模块接口？

## IT - 集成测试 (Integration Test)

### 特点

- **颗粒度**: 中等
- **测试对象**: 多个模块之间的协作
- **仿真时间**: 较长
- **覆盖率要求**: 中等，重点覆盖接口和场景

### 关注点

1. **总线接口**
   - AXI/AHB/APB协议一致性
   - 突发传输正确性
   - 握手时序

2. **模块间通信**
   - 中断传递
   - 握手信号
   - 数据Buffer交换

3. **跨时钟域**
   - 同步机制
   - 数据一致性
   - CDC故障检测

4. **系统场景**
   - 多模块并发
   - 资源竞争
   - 死锁检测

### 典型测试点

```
IT-001: CPU通过AXI读取DDR数据
IT-002: DMA在AXI总线上发起突发传输
IT-003: SPI中断触发CPU响应
IT-004: ETH模块与CPU共享DDR
IT-005: 两个AXI Master仲裁
IT-006: 跨时钟域数据稳定传递
IT-007: 模块A通过APB配置模块B寄存器
IT-008: 系统复位后各模块正确初始化
```

### 判断标准

测试点是否属于IT级：
- [ ] 是否涉及多个模块协作？
- [ ] 是否涉及总线协议？
- [ ] 是否涉及跨时钟域？
- [ ] 是否涉及中断/握手机制？

## ST - 系统测试 (System Test)

### 特点

- **颗粒度**: 最粗
- **测试对象**: 整个芯片/系统
- **仿真时间**: 最长
- **覆盖率要求**: 场景覆盖为主

### 关注点

1. **系统级场景**
   - 启动/关机流程
   - 低功耗模式切换
   - 引导加载

2. **多模块协作**
   - 真实应用场景
   - 真实协议栈
   - 真实软件交互

3. **性能指标**
   - 吞吐量
   - 延迟
   - 带宽

4. **系统级边界**
   - 电源边界
   - 温度边界
   - 老化效应

### 典型测试点

```
ST-001: 芯片上电后完整启动流程
ST-002: 从NOR Flash引导启动
ST-003: DDR初始化并正确访问
ST-004: 以太网收发完整数据帧
ST-005: USB枚举和Bulk传输
ST-006: 低功耗IDLE模式进入和退出
ST-007: 看门狗复位整个系统
ST-008: 多核启动和核间通信
```

### 判断标准

测试点是否属于ST级：
- [ ] 是否涉及整个系统？
- [ ] 是否需要真实软件/固件？
- [ ] 是否关注性能指标？
- [ ] 是否涉及多模块真实协作？

## 层级的拆分与合并

### 从ST到UT的拆分

一个ST级测试点可以拆分为多个IT/BT/UT级测试点：

**ST场景**: "以太网Ping功能"
```
├── IT-ETH-001: ETH模块与CPU通过AXI共享DDR
├── IT-ETH-002: ETH中断触发TCP/IP处理
├── BT-ETH-001: ETH MAC帧接收正确解析
├── BT-ETH-002: ETH CRC校验正确
├── UT-ETH-001: MAC地址匹配逻辑
├── UT-ETH-002: CRC32计算电路正确
```

### 从UT到ST的合并

多个UT/BT测试点可以合并为一个ST场景：

**UT/BT测试点**:
```
UT-ETH-001: MAC地址匹配
BT-ETH-001: 帧接收解析
IT-ETH-001: 中断机制
IT-CPU-001: DDR访问
```

**合并为ST场景**: "ETH Ping响应"

## 测试点溯源分析

当发现一个bug时，应该能够溯源到具体的验证层级：

| Bug类型 | 应该在哪个层级发现 | 说明 |
|--------|------------------|------|
| 状态机死机 | UT | 状态机覆盖不足 |
| 寄存器配置不生效 | BT | 配置-功能路径未覆盖 |
| 总线死锁 | IT | 多Master仲裁场景未覆盖 |
| 系统启动失败 | ST | 真实场景未覆盖 |

## 验证计划编制原则

1. **完整性**: 覆盖所有层级
2. **颗粒度匹配**: 层级内测试点颗粒度一致
3. **避免冗余**: 跨层级测试点不应重复
4. **可追溯**: 每个测试点可追溯到设计Spec
5. **优先级**: P0测试点必须覆盖
