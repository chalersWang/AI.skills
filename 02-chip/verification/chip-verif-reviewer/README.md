# Chip Verification Reviewer

芯片验证测试点评审AI Skill —— 像资深芯片验证工程师一样review测试点。

## 功能概述

装备该skill后，AI大模型能够：

1. **分层评审** - 根据测试点所属验证层级（ST/IT/BT/UT）提供不同颗粒度的审查建议
2. **专业建议** - 像资深工程师一样对测试点进行详细评审，发现遗漏和不足
3. **Checklist管理** - 支持随时添加新的测试点checklist到skill知识库
4. **持续完善** - 不断学习和积累新的验证知识

## 验证层级

| 层级 | 全称 | 颗粒度 | 关注重点 |
|------|------|--------|---------|
| **ST** | System Test | 最粗 | 系统整体行为、跨模块协作、功耗、性能 |
| **IT** | Integration Test | 中等 | 模块接口、协议一致性、跨时钟域 |
| **BT** | Block Test | 较细 | 模块功能、边界case、错误响应 |
| **UT** | Unit Test | 最细 | 信号级、功能点、状态机、计数器 |

## 快速使用

### 1. 基本评审流程

当用户提供测试点进行评审时：

```
1. AI识别测试点对应的验证层级（ST/IT/BT/UT）
2. 按照该层级的审查重点进行分析
3. 输出具体的改进建议和补充测试点
4. 询问用户是否需要添加新测试点到知识库
```

### 2. 输入格式

支持以下形式的测试点输入：

- **Excel文件** (.xlsx/.xls) - 表格形式的测试点
- **Markdown** - Markdown格式的测试点列表
- **纯文本** - 自由格式的测试点描述

示例输入（Markdown格式）：

```markdown
# AXI总线测试点

## 1. 基本读写测试
- 测试读请求，验证数据正确
- 测试写请求，验证写入正确

## 2. 握手信号
- 检查VALID和READY
```

### 3. 输出格式

评审完成后，AI会输出：

```markdown
## 评审结果

### 原测试点
[原始测试点内容]

### 评审意见
[详细评审建议，包括：
- 总体评价
- 具体问题分析
- 遗漏项指出]

### 建议补充
| 补充测试点 | 验证层级 | 说明 |
|-----------|---------|------|
| [具体补充内容] | IT | [补充原因] |
```

## 添加新的Checklist

### 方法1: 通过对话添加

告诉AI：
> "把XXX的测试点添加到skill知识库"

AI会自动创建对应的checklist文件。

### 方法2: 手动创建

1. 在 `references/` 目录下创建新的checklist文件：
   ```
   references/checklist_<主题>.md
   ```

2. 遵循标准格式：

```markdown
# [主题] 测试点Checklist

## 概述
[简要说明]

## 测试点分类

### 1. 功能测试
- [测试点1]
- [测试点2]

### 2. 边界测试
- [测试点1]
- [测试点2]

### 3. 异常测试
- [测试点1]
- [测试点2]
```

3. 更新 `SKILL.md` 中的引用

## 分层评审标准

### ST级 (System Test) 审查重点

- 系统级场景完整性（启动、运行、关机流程）
- 多模块协作场景
- 功耗和性能测试点
- 系统级边界条件

### IT级 (Integration Test) 审查重点

- 总线协议一致性（AXI/AHB/APB）
- 跨时钟域处理
- 模块间接口时序
- 中断和握手信号
- 错误传播路径

### BT级 (Block Test) 审查重点

- 模块功能覆盖
- 边界值和极值测试
- 错误注入和响应
- 寄存器配置
- 配置-功能对应关系

### UT级 (Unit Test) 审查重点

- 信号级时序
- 状态机覆盖（正常、异常、边界）
- 计数器精度
- 组合逻辑穷举
- 同步/异步电路

## 使用示例

### 示例1: 评审AXI测试点

```

3. 地址通道验证不足：缺少对齐、边界等测试

### 建议补充
| 补充测试点 | 验证层级 | 说明 |
|-----------|---------|------|
| INCR4突发读测试 | IT | 增量突发验证 |
| 握手时序组合测试 | IT | 6种时序覆盖 |
| ... | ... | ... |
```

## 最佳实践

1. **选择正确的验证层级**: 根据测试点内容判断所属层级，确保评审颗粒度合适
2. **关注边界条件**: 边界和异常场景往往是最容易出问题的地方
3. **保持Checklist更新**: 不断添加新的测试点，完善知识库
4. **分层细化**: ST级发现的问题应分解到IT/BT/UT级分别验证

## 限制与注意事项

1. 该skill专注于验证测试点的review，不涉及实际验证环境的搭建
2. 评审建议供参考，具体实现需结合实际项目情况
3. 新添加的Checklist需要定期review和更新
