# Chip Verification Testpoint Reviewer

## Overview

该skill使AI能够像资深芯片验证工程师一样对验证测试点进行专业评审。通过分析测试点内容及其所属验证层级（ST/IT/BT/UT），提供具体、详细的改进和补充建议。

## 核心功能

1. **分层评审**: 根据验证层级提供不同颗粒度的建议
   - ST (System Test): 系统级验证，关注整体系统行为、接口协作、功耗、性能
   - IT (Integration Test): 集成测试，关注模块间接口、协议一致性、边界条件
   - BT (Block Test): 模块级验证，关注模块内部功能、边界case、错误处理
   - UT (Unit Test): 单元测试，关注信号级、功能点、状态机、计数器

2. **多维度审查**: 覆盖功能、边界、异常、协议、性能、覆盖率等维度

3. **Checklist管理**: 支持添加新测试点到skill的checklist知识库

## 验证层级与颗粒度

| 层级 | 缩写 | 颗粒度 | 关注重点 |
|------|------|--------|---------|
| System Test | ST | 最粗 | 系统整体行为、跨模块协作、功耗、性能 |
| Integration Test | IT | 中等 | 模块接口、协议一致性、跨时钟域 |
| Block Test | BT | 较细 | 模块功能、边界case、错误响应 |
| Unit Test | UT | 最细 | 信号级、功能点、状态机、计数器 |

## 审查流程

### Step 1: 确定验证层级

分析测试点内容，判断所属验证层级：

- **ST**: 涉及多模块协作、系统级场景、功耗分析、性能测试
- **IT**: 涉及模块间接口、AXI/AHB/APB等总线协议、跨时钟域
- **BT**: 针对单个模块的功能验证、边界条件、错误注入
- **UT**: 针对具体信号、寄存器、状态机、计数器的测试

### Step 2: 多维度审查

针对不同层级，关注以下审查维度：

**ST级审查重点:**
- 系统级场景完整性（启动、运行、关机流程）
- 多模块协作场景
- 功耗和性能测试点
- 系统级边界条件

**IT级审查重点:**
- 总线协议一致性（AXI/AHB/APB）
- 跨时钟域处理
- 模块间接口时序
- 中断和握手信号
- 错误传播路径

**BT级审查重点:**
- 模块功能覆盖
- 边界值和极值测试
- 错误注入和响应
- 寄存器配置
- 配置-功能对应关系

**UT级审查重点:**
- 信号级时序
- 状态机覆盖（正常、异常、边界）
- 计数器精度
- 组合逻辑穷举
- 同步/异步电路

### Step 3: 输出改进建议

对每个测试点，输出：
1. **原测试点内容**: 保持原文
2. **评审意见**: 具体、专业的改进建议
3. **补充测试点**: 建议添加的新测试点

## 评审输出格式

```markdown
## 评审结果

### 原测试点
[原始测试点内容]

### 评审意见
[详细评审建议]

### 建议补充
| 补充测试点 | 验证层级 | 说明 |
|-----------|---------|------|
| [补充内容] | [ST/IT/BT/UT] | [说明] |
```

## 添加新Checklist

当需要将新的测试点纳入skill知识库时：

1. 创建新的reference文件：`references/checklist_<主题>.md`
2. 按照格式编写新checklist
3. 更新SKILL.md中的引用

### 新Checklist格式

```markdown
# [主题] 测试点Checklist

## 概述
[简要说明]

## 测试点分类

### 1. 功能测试
- [测试点1]
- [测试点2]

### 2. 边界测试
- [测试点1]
- [测试点2]

### 3. 异常测试
- [测试点1]
- [测试点2]
```

## 快速使用

当用户提供测试点进行评审时：

1. 识别测试点对应的验证层级（ST/IT/BT/UT）
2. 按照该层级的审查重点进行分析
3. 输出具体的改进建议和补充测试点
4. 如有必要，询问用户是否需要添加新测试点到知识库
